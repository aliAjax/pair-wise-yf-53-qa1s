# pair-wise-yf-53 开源项目发布列车准备和门禁控制台

## 源提示词摘要
维护者创建跨仓库发布，关联版本、负责人、阻断问题和待合并依赖，安排冻结时间与分批顺序。发布前检查依赖、阻断、超时确认和顺序冲突，支持冻结、降级、回滚准备状态及可追溯审计。

## 技术栈
React Router 7 框架模式 + TypeScript + Mantine + Redux Toolkit + RTK Query + React Hook Form + Zod + Lingui + dnd-kit。

## 已实现闭环
- 跨仓库发布列车、依赖门禁和阻断问题三类业务对象。
- 门禁确认、阻断关闭、发布冻结、回滚和恢复准备状态。
- 仓库顺序拖拽、表单校验、远端健康查询与审计历史。
- 持久化采用「修订号 + 比较并交换（CAS）」，不再整页覆盖；跨标签页通过 storage 事件对齐。

## 冻结批次（可恢复）
旧版本把整页状态写入 localStorage，两个值班员后保存的整页快照会盖掉对方的决定。现在冻结、降级与门禁确认都收敛到冻结批次：

- **开始批次固定快照**：仓库分批顺序、每个门禁版本、阻断项开闭状态在批次开始时快照固定；批次由计划指纹派生幂等键，重复开始请求沿用首次批次。
- **可恢复执行**：单项确认失败保留已处理仓库，只重试未完成项（pending/failed）；已确认/已降级仓库不动。
- **降级保留现场**：门禁无法满足时可降级，门禁维持 blocked 并记录原因，随列车冻结保留现场。
- **失效与释放**：阻断项重开、冻结时间/顺序变更、回滚会使进行中批次失效；未执行确认释放顺序占用，已确认/已降级仓库保留现场。
- **并发提交**：所有写入带期望修订号，两人前后脚提交同一批次时后到者按 CAS 检出冲突仓库（决定一致自动合并，否则沿用先到决定），旧整页快照归档为历史批次。
- **旧数据迁移**：v1 整页状态首次加载即迁移为 schema v2，既有门禁决定生成历史批次；冲突归档同样进入历史批次列表。

代码组织：`app/store/freeze.ts` 为纯领域模型（无 DOM），`app/store/storage.ts` 为 CAS 持久化，`app/store/index.ts` 为 Redux 与用例 thunks。
